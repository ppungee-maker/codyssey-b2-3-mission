> **이 문서는 무엇인가요?**

> AI 도구나 자동화 툴을 한 번도 안 써본 사람이 위에서 아래로 그대로 읽고 따라 하면
> 같은 결과물을 만들 수 있도록, **용어 → 준비물 → 클릭 순서 → 실제 결과 → 왜 그렇게 했는지**

## 1. 5분 요약 — 무엇을 만드는 건가요?

"텀블러 신제품 출시" 라는 **주제 한 줄만 입력**하면,

- 인스타그램용 **짧은 캡션 + 해시태그**
- 블로그용 **500자 이상 본문 + 소제목**
- X(트위터)용 **280자 이내 요약**
- 그리고 **대표 이미지 1장**

이 자동으로 만들어져 **Notion 한 페이지에 플랫폼별로 정리되어 저장**되는 시스템입니다.

사람이 하면 30~40분 걸리는 일(같은 내용을 세 번 고쳐 쓰기)을 **주제 입력 1회 + 대기 1분**으로 바꿉니다.

## 2. 용어 사전 — 이 단어만 알면 나머지는 쉽습니다

| 용어 | 쉬운 설명 | 이 프로젝트에서는 |
|---|---|---|
| **워크플로우** | "이거 하고 → 그다음 이거 하고" 순서를 미리 그려둔 것 | 주제 입력 → 텍스트 3개 생성 → 이미지 생성 → Notion 저장 |
| **트리거(trigger)** | 워크플로우를 **시작시키는 방아쇠** | 웹 폼에 주제를 넣고 [전송]을 누르는 순간 |
| **웹훅(Webhook)** | "여기로 데이터 보내주세요" 라고 알려주는 **전용 주소(URL)** | Make 가 만들어주는 주소. 폼이 그 주소로 주제를 보냄 |
| **라우터(Router)** | 하나의 흐름을 **여러 갈래로 나누는 분기점** | 플랫폼 3개(인스타/블로그/X)로 3갈래 |
| **프롬프트(prompt)** | AI 에게 시키는 **주문서** | "280자 이내로, 해시태그 2개만" 같은 조건문 |
| **톤앤매너** | 글의 **말투와 분위기** | 인스타=친근한 해요체 / 블로그=차분한 합니다체 |
| **모듈(module)** | Make 화면에서 동그라미 하나 = **작업 한 개** | HTTP 호출 모듈, Notion 저장 모듈 등 |
| **Notion DB 속성** | 표의 **열(칼럼)**. 타입(글자/날짜/선택)이 정해져 있음 | 주제(Title) · 플랫폼(Select) · 콘텐츠(Text) · 이미지(Files) |
| **vt(가상 토큰)** | 네이토가 쓰는 **사용량 단위**. 길게 답할수록 많이 씀 | 이번 텍스트 8회 생성에 총 약 1,600 vt |

## 4. 전체 그림 (워크플로우 구조)

```
[1] 주제 입력 (Make Webhook 또는 Google Forms)
      예: "친환경 텀블러 신제품 출시 (한밭보틀, 재생 스테인리스 70%, 6시간 보온, 3만원대)"
        │
        ▼
[2] Router — 3갈래 분기 (인스타그램 / 블로그 / X)
        │              │              │
        ▼              ▼              ▼
[3a] 인스타 프롬프트  [3b] 블로그 프롬프트  [3c] X 프롬프트
     (§5-1)              (§5-2)              (§5-3)
     HTTP 호출 → 생성 AI  HTTP 호출 → 생성 AI  HTTP 호출 → 생성 AI
        │              │              │
        └──────┬───────┴──────┬───────┘
               ▼              
[4] 대표 이미지 생성 (이미지 프롬프트 §5-4) — 1회만 호출해 3플랫폼이 공유
               │
               ▼
[5] Notion DB 저장 — 플랫폼별로 **행 3개** 생성 (주제/플랫폼/콘텐츠/이미지)
               │
               ▼
[6] 실패 처리 — 어느 단계든 실패하면 재시도 1회 → 그래도 실패면 "실패" 행 기록 후 진행
```

**단계별 역할과 연결**

| 단계 | 역할 | 앞 단계에서 받는 것 | 다음 단계로 넘기는 것 |
|---|---|---|---|
| [1] 입력 | 주제 문자열 확보 | (사람의 입력) | `topic` |
| [2] Router | 플랫폼 수만큼 복제 | `topic` | `topic` + `platform` |
| [3] 텍스트 생성 | 플랫폼 규격에 맞는 문장 만들기 | `topic`, `platform` | `content` |
| [4] 이미지 생성 | 대표 이미지 1장 | `topic` | 이미지 URL |
| [5] 저장 | 팀이 볼 수 있게 남기기 | `content`, 이미지 URL | Notion 행 3개 |
| [6] 실패 처리 | 중단 없이 흐름 유지 | 오류 메시지 | 실패 로그 행 |

> **왜 이미지를 3갈래 안이 아니라 밖에서 1번만 만드나요?**
> 같은 주제면 대표 이미지는 하나로 충분한데, 3갈래 안에 넣으면 **같은 이미지를 3번 만들어 비용이 3배**가 됩니다.
> 이렇게 "여러 갈래가 공유하는 작업은 갈래 밖으로 빼기" 가 자동화 설계의 기본기입니다.

## 5. 프롬프트 템플릿 3종 + 이미지 프롬프트 (초안 → 최종)

여기가 이 미션의 **핵심**입니다. 채점도 결과물보다 "왜 그렇게 고쳤는지" 를 봅니다.
아래 모든 응답은 **실제로 네이토에 물어서 받은 원문**이며 전문은 [`outputs/`](outputs/) 에 있습니다.

### 5-1. 인스타그램 — 짧은 캡션 + 해시태그 10개 내외

**초안 프롬프트(v1)**
```
다음 주제로 인스타그램 게시글 캡션을 써줘.
주제: {topic}
```
→ 결과: `---` 구분선과 `📍 Point` 불릿이 멋대로 붙고 이모지 6개, 해시태그 9개.
자동 저장하려면 "캡션"과 "해시태그"를 분리해야 하는데 **구조가 매번 달라 파싱이 불가능**했습니다.

**최종 프롬프트(v2)**
```
역할: 소셜 콘텐츠 자동생성 파이프라인의 인스타그램 텍스트 생성 단계.
출력 형식: 캡션 본문 → 빈 줄 → 해시태그 한 줄. 그 외 머리말·설명·따옴표 금지.
캡션 규칙: 첫 줄은 8~14자 훅, 전체 3~4문장·300자 이내, 이모지 2~3개(문장 끝에만),
          친근한 구어체(해요체).
해시태그 규칙: 10개 내외, 한글 6개 + 영문 4개, 브랜드명 1개 포함, '#' 로 시작하고 공백 구분.
금지: 의학적·환경 효과 과장('완전 무해', '탄소 제로'), 가격 할인 단정, 없는 스펙 창작.
주제: {topic}
```
→ 결과(실측): 전체 220자 · 해시태그 **10개** · 이모지 **3개** · 불필요한 구분선 0개.

**무엇을 바꿨고 왜 바뀌었나 (3가지)**
1. **역할(role) 문장을 맨 앞에 붙였다** — "파이프라인의 한 단계" 라고 알려주면 AI 가 사람에게 말 걸듯 설명하는 습관("이렇게 써보세요~")을 멈춥니다.
2. **출력 형식을 그림처럼 지정했다** — "캡션 → 빈 줄 → 해시태그 한 줄". 자동화는 **모양이 일정해야** 다음 단계에서 자를 수 있습니다.
3. **금지 목록을 넣었다** — AI 는 칭찬을 잘합니다. 광고에서 문제가 되는 과장을 미리 막는 것이 사후 검수보다 쌉니다.

### 5-2. 블로그 — 500자 이상 + 소제목 구조

**초안 프롬프트(v1)**: `다음 주제로 블로그 게시글 본문을 써줘. 500자 이상.`
→ 결과: 길이는 충족(1,053자)했지만 소제목을 `## ` 대신 **1. 굵은 글씨**로 만들어 마크다운 구조가 깨졌고,
'기적', '획기적', '탁월한' 처럼 **근거 없는 강조어가 3곳** 등장했습니다.

**최종 프롬프트(v2)**
```
역할: 소셜 콘텐츠 자동생성 파이프라인의 블로그 텍스트 생성 단계.
출력 형식: '# 제목' 한 줄 → 본문. 머리말·설명·마무리 인사말 금지.
규칙: 본문 500자 이상 900자 이내, '## 소제목' 2~3개, 각 소제목 아래 3문장 이상,
      정보 전달 위주 문어체(합니다체), 이모지 금지.
금지: 환경 효과 과장('완전 무해'·'탄소 제로'), 없는 스펙·수치 창작, 경쟁사 비방.
주제: {topic}
```
→ 결과(실측): 1,012자 · `## 소제목` **3개** · 이모지 0개 · 과장어를 '완화하는 데 기여하고자 합니다' 같은 **수위 낮춘 서술**로 대체.

**핵심 교훈**: 길이만 지정하면 AI 는 **길이는 맞추고 구조는 자기 멋대로** 만듭니다.
자동화에서는 길이보다 **구조(제목/소제목 마크업)** 지정이 더 중요합니다.

### 5-3. X(트위터) — 280자 이내

**초안 프롬프트(v1)**: `다음 주제로 X(트위터) 게시글을 써줘.`
→ 결과: ✅ 불릿 3줄 + 이모지 6개 + 해시태그 5개. **인스타 스타일이 그대로 나왔습니다**(플랫폼 구분 실패).

**최종 프롬프트(v2)**
```
역할: 소셜 콘텐츠 자동생성 파이프라인의 X(트위터) 텍스트 생성 단계.
출력 형식: 게시글 한 덩어리만. 머리말·설명·따옴표·불릿(✅ 등) 금지.
규칙: 공백 포함 280자 이내(반드시 준수), 2~3문장, 핵심 정보 1~2가지만,
      해시태그 1~2개를 마지막에, 이모지 최대 1개.
금지: 환경 효과 과장, 없는 스펙 창작.
주제: {topic}
```
→ 결과(실측): **103자**(제한의 37%) · 2문장 · 해시태그 2개 · 이모지 1개.

**왜 280자보다 훨씬 짧게 나오게 뒀나요?** 실제 게시할 때 URL(t.co 링크는 23자로 계산)이나
멘션이 붙기 때문에 **여유(마진)** 를 남겨야 잘리지 않습니다. 상한에 딱 맞추는 건 위험합니다.

### 5-4. 이미지 프롬프트 (실제 생성 완료 ✅)

## 6. Notion 저장 구조 (플랫폼별 구분 저장)

| 속성명 | 타입 | 무엇이 들어가나 | 왜 이 타입인가 |
|---|---|---|---|
| 주제 | Title | `친환경 텀블러 신제품 출시…` | Notion DB 는 Title 이 필수 1개. 검색·정렬 기준이 됨 |
| 플랫폼 | Select | `인스타그램` / `블로그` / `X` | 자유 입력(Text)으로 두면 '트위터'·'X'·'x' 가 섞여 필터가 깨짐 |
| 콘텐츠 | Text | 생성된 본문 전체 | 길이 제한이 넉넉하고 줄바꿈 보존 |
| 이미지 | Files & media | 대표 이미지 | URL(Text)로 두면 미리보기가 안 뜸 |
| 생성일시 | Date | 자동화 실행 시각 | 같은 주제를 재생성했을 때 버전 구분 |
| 톤(보너스) | Select | `A-친근` / `B-전문` | A/B 테스트 결과를 같은 표에서 비교하기 위함 |

**행을 3개 만드는 이유**: 한 행에 3플랫폼을 다 넣으면 "인스타만 보기" 필터가 불가능합니다.
**플랫폼 = 행**, **속성 = 열** 로 쪼개는 것이 나중에 관리가 편합니다.

## 10. 자주 겪는 문제와 해결 (실제로 겪은 것만)

| 증상 | 원인 | 해결 |
|---|---|---|
| AI 가 요청 안 한 설명·머리말을 붙인다 | 프롬프트에 **역할·출력 형식**이 없음 | "역할: …단계", "출력 형식: …. 머리말 금지" 두 줄 추가 |
| 같은 프롬프트인데 매번 구조가 다르다 | 형식을 문장으로만 부탁했음 | 형식을 **화살표 도식**으로 지정(`캡션 → 빈 줄 → 해시태그 한 줄`) |
| 글자수 제한을 넘긴다 | 숫자를 안 박거나 "정도" 로 표현 | "공백 포함 280자 이내(반드시 준수)" 처럼 **단위+강제어** 명시 |
| 이미지 속 글자가 뭉개진다 | 이미지 AI 의 구조적 한계 | 프롬프트에 `no text anywhere in the image` 로 **글자 자체를 배제** |
| 과장 광고 문구가 섞인다 | AI 의 기본 성향(칭찬) | **금지 목록**을 프롬프트에 명시 |
| 명령줄에서 AI 호출이 멈춘 것처럼 보인다 | 표준입력(stdin)이 열린 채 대기 | 호출 끝에 `< /dev/null` 을 붙여 입력을 닫아준다 |
