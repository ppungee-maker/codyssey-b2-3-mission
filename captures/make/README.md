## 1. Notion DB 속성 (6개)

새 페이지 → `/database - full page`:

| 속성명 | 타입 | 들어갈 값 |
|---|---|---|
| 주제 | Title | `친환경 텀블러 신제품 출시 (한밭보틀…)` |
| 플랫폼 | Select (`인스타그램`/`블로그`/`X`) | 행마다 하나 |
| 콘텐츠 | Text | 해당 플랫폼 최종본 전문 |
| 이미지 | Files & media | 대표 이미지 업로드 |
| 생성일시 | Date | 만든 날짜 |
| 톤(보너스) | Select (`A-친근`/`B-전문`) | A/B 행을 추가할 때만 |

- **행 = 플랫폼**으로 쪼개는 이유: 한 행에 3플랫폼을 넣으면 "인스타만 보기" 필터가 불가능하다.
- `플랫폼`·`톤` 을 Select 로 고정하는 이유: 자유 입력이면 `X`/`트위터`/`x` 가 섞여 필터가 깨진다.
- 만든 뒤 `···` → `Connections` → Make Integration 연결(Make 배선 단계에서 필요).
- `Share` → 링크 공유 → **그 링크를 루트 README 상단 진행상태 표에 한 줄 추가**.

## 2. Make 시나리오 배선 (모듈 6개)

> ⚠️ **함정: AI 생성 단계는 네이토로 못 만든다.** 네이토는 `JSESSIONID` **세션 쿠키** 인증 +
> `check-ip` IP 허용목록이라 외부 서비스가 붙을 방법이 없다(API 키가 존재하지 않는다).
> 실연동에서는 **Google AI Studio(Gemini) 무료 키** 또는 OpenAI 키로 갈고, **프롬프트는 루트
> README §5-1~5-3 최종본을 그대로** 쓴다. 작업 후 루트 README 도구 표를
> "텍스트 생성 = 네이토(프롬프트 개발) / 실연동 = Gemini API" 로 정정한다.

| # | 모듈 | 설정 |
|---|---|---|
| 1 | `Webhooks > Custom webhook` | 생성된 주소 복사. 입력 필드 `topic` 하나만 받는다 |
| 2 | `Router` | 갈래 3개 |
| 3a | `HTTP > Make a request` | 인스타 프롬프트(§5-1 최종) + `{{1.topic}}` |
| 3b | `HTTP > Make a request` | 블로그 프롬프트(§5-2 최종) |
| 3c | `HTTP > Make a request` | X 프롬프트(§5-3 최종) |
| 4 | `HTTP` 또는 이미지 모듈 | 대표 이미지 1회 생성 — **Router 밖**에 둔다(안에 넣으면 3배 비용, 루트 README §4 근거) |
| 5 | 각 갈래 끝 `Notion > Create a Database Item` | §1 속성 매핑. `플랫폼` 은 갈래마다 고정값 |
| 6 | 3·5번 우클릭 → `Add error handler` → `Break` | `Number of attempts` 1~2, 실패 시 계속 진행 |

트리거 테스트: 웹훅 주소로 `{"topic":"친환경 텀블러 신제품 출시 (한밭보틀, 재생 스테인리스 70%, 6시간 보온, 3만원대)"}`
를 보내면(Make 의 `Run once` + 브라우저 주소창 호출 또는 Google Forms 연결) 시나리오가 돈다.
